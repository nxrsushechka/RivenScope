# Проверка и исправления 0.1.1 — 10 ноября 2026

## Результат

Восстановлен полный исходный код приложения. Разработка, тестирование, сборка и
изолированная установка теперь выполняются из `src/`, без готового wheel или
старого `build/lib`. Рыночный мониторинг контрактов остаётся недоступен: эта версия
не заявляет полного выполнения исходного ТЗ.

## Исправлено

- В `src/rivenscope` восстановлены `app.py`, `analysis.py`, `ui/` и SVG icon.
  Исходные восстановленные файлы сверены побайтно с прежним release wheel 0.1.0.
- Старые отслеживаемые `build/`, `dist/` и Python 3.14 bytecode удалены из дерева
  проекта. В cloud workspace сохранена проверенная копия прежних артефактов вне
  репозитория: `/workspace/onboarding-rivenscope/legacy-generated-artifacts.tar.gz`.
  Новые локальные результаты сборки по-прежнему идут в игнорируемый `dist/`.
- Сборщик использует чистый временный каталог и явный набор исходников. Он не
  переносит удалённые модули из старого build, не включает venv/cache/egg-info и
  нормализует permissions/timestamps. Версия читается из `pyproject.toml`.
- Возврат неизменившегося объявления из `potentially_missing` в `active` создаёт
  один snapshot и `status_changed`; повторный ответ не дублирует событие.
- Текущая аналитика использует свежие активные direct asks, исключает закрытые,
  исчезнувшие и будущие наблюдения. История при этом сохраняется. Счётчик выгодных
  оценок учитывает выбранное оружие, статус и свежесть.
- Comparables выбираются из базы независимо от открытой страницы таблицы, с
  совместимыми weapon/category/rank/disposition/context и signed-attribute set.
  Сохраняется явное ограничение 10 000 последних совместимых asks. Кэш оценки
  учитывает изменения цели и выборки.
- HTTP-тесты учитывают нечувствительность имён заголовков к регистру.
- Установщик записывает в launcher тот Python, на котором прошёл staging smoke,
  вместо жёсткого `/usr/bin/python`. `--data-dir` не обращается к default XDG dirs.
- Убрана зависимость тестов от заранее созданного `/tmp/opencode`.
- Добавлен `requirements-dev.txt` с PySide6 6.8.3 для Python 3.12/3.13 и CI workflow
  для этих двух версий Python. Удалённый GitHub Actions здесь не запускался.

## Проверки

Среда текущего прогона: Linux cloud, Python 3.12.14, PySide6/Qt 6.8.3, offscreen.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
QT_QPA_PLATFORM=offscreen PYTHONPATH=src RIVENSCOPE_PACKAGING=1 \
  .venv/bin/python -m unittest discover -s tests -t . -v
```

Полный прогон: **63 passed, 0 failed, 0 skipped**. Включены:

- parsing, фильтры, оценка, планировщик, HTTP failures/headers/timeouts;
- SQLite, миграции, backup/restore, import/export и regression tests;
- Qt UI, 100 000 строк, repeated start/stop и clean shutdown;
- установка, повторная установка и удаление с сохранением данных;
- запуск установленной версии в пути с пробелами с изолированным профилем;
- полнота wheel относительно исходников и отсутствие test fixtures в wheel;
- повторяемость SHA256 wheel/source archive;
- пересборка из source archive с намеренно добавленным старым build-модулем:
  артефакты идентичны, старый модуль отсутствует в wheel.

`pip check` проходит. Аудиосервер в cloud недоступен; успешный GUI smoke не
подтверждает слышимость звука или desktop notifications. Qt 6.12 ранее падал
при аудиоинициализации в этой sandbox-среде; это не доказательство сбоя на Omarchy.
Закреплённый dev runtime 6.8.3 не поддерживает Python 3.14. На Omarchy с Python 3.14
нужен совместимый системный PySide6; новый native-прогон на этой системе не выполнен.

Контролируемый soak 180 секунд: 682 обновления таблицы, ошибок 0, worker остановлен.
Разброс RSS после прогрева 0,56 МБ; UI heartbeat p99 69 мс, максимальная пауза
347 мс; CPU time 42,7 с. Исходный JSON: `test-artifacts/soak-0.1.1.json`.
Это локальная нагрузка с тестовыми объявлениями, не проверка реального рынка и
не доказательство многодневной стабильности. Часть прогона совпала с упаковочными
тестами в той же cloud-машине.

## Дополнительные проверки производительности и обновления

- Повторная установка текущего wheel теперь сохраняет предыдущий отличный release
  для отката. Новый regression test устанавливает две версии, повторяет новую
  установку и проверяет `current`, `previous` и сохранение SQLite/watchlist.
- Расчёт сопоставимости использует подготовленную выборку и ограниченный кэш
  расстояний, сохраняя индивидуальные исключения продавца/ID. На 120
  детерминированных сравнениях со старой реализацией результаты совпали побайтно
  после сериализации, включая confidence, comparables и объяснения.
- На одинаковой выборке из 1 000 объявлений полный холодный расчёт до изменения
  размера страницы ускорился с 19,04 до 2,97 с. Это контролируемые данные с
  повторяющимися характеристиками, не обещание ускорения любой рыночной выборки.
- Страница Market теперь содержит до 250 наблюдений перед локальной фильтрацией.
  Переход между страницами сохраняет доступ ко всем строкам. Сопоставимая выборка
  остаётся независимой от страницы и содержит до 10 000 asks.
- При закрытии окна расчёт отменяется; уже поставленные в очередь refresh-задачи
  не задерживают закрытие. При этом последний бюджет запросов сохраняется в БД.
  Проверено на рабочем Qt worker и 1 000 объявлениях.
- Полный прогон после этих изменений: 63 passed, 0 failed, 0 skipped.
- В базе из 10 000 сопоставимых объявлений первая страница (250 строк) рассчитана
  за 8,31 с, повторная — за 0,73 с; использованы 9 999 comparables на целевой объект.
  Расчёт выполняется в worker и отменяется при закрытии. Квадратичный характер
  некоторых вычислений остаётся: работа на миллионах строк не проверена.
  Замеры: `test-artifacts/market-baseline.json`, `market-optimized.json`,
  `market-large-database.json` в том же каталоге.
- После оптимизации повторён controlled soak на 90 секунд: 341 refresh, 0 ошибок,
  RSS после прогрева 0,16 МБ, heartbeat p99 70 мс (max 376 мс), clean shutdown.
  JSON: `test-artifacts/soak-performance.json`. Это короткий regression run,
  а не многодневная проверка рынка.

## Доступ к реальному рынку

Повторно получен официальный репозиторий документации
`https://github.com/42bytes-team/wfm-docs`, HEAD
`c76d86937c0aabf6269b7f44f1d32761eeee3030`. Его восемь страниц `docs/api/`
описывают manifests/orders/groups/users и прочие возможности, но не предоставляют
поддерживаемый route/schema поиска Riven contracts. `newOrders` описывает Order;
OAuth-регистрация сторонних приложений ещё не открыта. HEAD совпал с прежней
проверкой, новых возможностей не обнаружено.

Прямые HTTPS-запросы к docs.warframe.market/warframe.market блокирует proxy текущей
cloud-среды (`CONNECT 403`); свежая live-проверка API/ToS здесь не выполнена.
Для неё нужны разрешённые домены `api.warframe.market`, `docs.warframe.market`,
`warframe.market`. Разрешение доменов само по себе не открывает contract API.

Отсутствие документации не доказывает отсутствия внутреннего API. Для реализации
нужно подтверждение команды WFM о поддерживаемом способе интеграции. Готовый
запрос: [CONTRACT_ACCESS_REQUEST](CONTRACT_ACCESS_REQUEST.md). Сообщения и issues
от имени пользователя не отправлялись. Contract capability остаётся выключенной.
